OptiSim FTTx Lab

Guide de mise en œuvre en établissement

Ce guide s'adresse aux enseignants et au responsable informatique. Il décrit l'installation d'OptiSim sur les postes personnels des élèves et des enseignants, l'organisation d'une salle informatique en réseau avec un dossier partagé, et le déroulement d'une épreuve : sujets individuels, dépôt des copies, correction et notes.

Sommaire

  1. Les versions d'OptiSim et l'installation sur les postes personnels
  2. La salle informatique : architecture, dossier partagé et droits
  3. Créer le partage : paquets, script, vérifications, raccourcis
  4. Une épreuve pas à pas : avant, pendant, après
  5. Maintenance et sécurité : mises à jour, mot de passe, sauvegardes, limites

Principe : les élèves n'ont jamais accès à la version enseignant. Deux protections se cumulent : les droits du partage (dossier enseignant invisible) et le chiffrement de la version enseignant par le mot de passe de l'établissement.

Les paquets se construisent avec Node.js, dans le dossier du projet : OPTISIM_MDP='mot de passe' node outils/paquets.js. Ils sont dans dist/.

Élèves : s'exercer chez soi

  1. En ligne : ouvrir le site public d'OptiSim (version élève). Aucune installation.
  2. Hors ligne (PC, portable) : décompresser OptiSim-FTTx-Lab-eleve.zip et ouvrir index.html avec Chrome, Edge ou Firefox. Sous Windows, installer-eleve.cmd crée un raccourci sur le bureau (droits administrateur).
  3. Smartphone, tablette : le site s'ouvre, mais l'interface est conçue pour la souris et un grand écran. Il convient pour revoir la documentation et les livrets ; pour les TP, préférer un ordinateur.

Enseignants : préparer et corriger chez soi

  1. En ligne : adresse du site suivie de /enseignant/, puis le mot de passe de l'établissement. Lien « Se déconnecter » dans la barre d'état.
  2. Hors ligne : copier le dossier …-enseignant-protege (clé USB, ordinateur) et ouvrir index.html. Cocher « Rester connecté 12 h » seulement sur un poste personnel.
  3. Le paquet non protégé ne doit jamais être déposé sur un poste ou un partage accessible aux élèves.

Mot de passe de l'établissement : 12 caractères ou plus, communiqué aux seuls enseignants, changé à chaque rentrée. Pour le changer, on reconstruit les paquets avec le nouveau mot de passe et on redistribue.

2. La salle informatique en réseau

Prérequis

  • Un poste par élève, avec Chrome ou Edge récent. Firefox fonctionne aussi, mais sans la boîte « Enregistrer sous » de dossier : la copie va alors dans Téléchargements.
  • Un compte par élève (domaine ou comptes locaux) : sauvegarde automatique et reprise d'examen personnelles. À défaut, un compte par poste et un élève par poste.
  • Un dossier partagé : serveur de fichiers, NAS, ou partage Windows du poste enseignant pour une petite salle. Deux groupes : Élèves et Enseignants.
  • Aucune connexion Internet n'est nécessaire.

Arborescence et droits

Dossier du partage \\serveur\OptiSimÉlèvesEnseignants
Application\ — version élèvelecturelecture
Sujets\<classe>\ — sujets nominatifslecturemodification
Copies\<classe>\ — dépôt des copiesdépôt seul : créer et remplacer sa copie, sans voir celles des autresmodification
Enseignant\ — Version-enseignant (protégée), Corriges, Notes, Archivesaucun accès : dossier invisiblemodification

Le partage utilise l'énumération basée sur l'accès : chacun ne voit que les dossiers auxquels il a droit. Un élève ne voit donc ni Enseignant, ni les copies de ses camarades.

Circulation des fichiers

Enseignant : sujets individuels→ Sujets\classe →Élève : Ouvrir son sujet→ Rendre ma copie →Copies\classe→ Ouvrir un dossier de copies →Enseignant : notes, journal, CSV

Le corrigé des sujets individuels (CORRIGE-….csv) et les notes vont toujours dans Enseignant\, jamais dans Sujets ni dans Copies.

3. Créer le partage (responsable informatique)

  1. Construire les paquets sur un poste disposant de Node.js : OPTISIM_MDP='…' node outils/paquets.js. Copier dist\OptiSim-FTTx-Lab-eleve, dist\OptiSim-FTTx-Lab-enseignant-protege et creer-partage.ps1 sur le serveur.
  2. Créer les groupes Élèves et Enseignants (domaine ou groupes locaux) et y placer les comptes.
  3. Simuler, dans PowerShell administrateur — rien n'est modifié, les actions sont affichées :
    .\creer-partage.ps1 -Racine D:\Partages\OptiSim -GroupeEleves "LYCEE\Eleves" -GroupeEnseignants "LYCEE\Enseignants" -Classes "1TEL-A","1TEL-B" -PaquetEleve .\OptiSim-FTTx-Lab-eleve -PaquetEnseignant .\OptiSim-FTTx-Lab-enseignant-protege -Simulation
  4. Appliquer : relancer la même commande sans -Simulation. Le script crée les dossiers, applique les droits, copie les paquets et crée le partage. Il refuse de copier une version enseignant non protégée.
  5. Raccourcis : par stratégie de groupe (GPO, préférences « Raccourcis »), un raccourci « OptiSim FTTx Lab » vers \\serveur\OptiSim\Application\index.html sur le bureau des élèves ; pour les enseignants, un second vers \\serveur\OptiSim\Enseignant\Version-enseignant\index.html.

4. Une épreuve pas à pas

Avant : l'enseignant prépare les sujets

  1. Ouvrir la version enseignant, charger le TP (correction) ou son propre réseau ; régler éventuellement le mode recette (fiche de recette).
  2. Examen → titre, durée, consignes, barème ; partie Sujets individuels : coller la liste de la classe (un élève par ligne), choisir le nombre de pannes optiques et de configuration.
  3. Écrire les sujets dans un dossier… → choisir Sujets\<classe> ; puis enregistrer le corrigé dans Enseignant\Corriges. Le navigateur retient ces dossiers pour la fois suivante.

Pendant : les élèves composent

  1. Ouvrir → Sujets\<classe> → son sujet (son nom s'affiche). Le réseau est verrouillé ; mesures, interventions et réglages sont enregistrés dans un journal.
  2. En cas de fermeture du navigateur, l'examen reprend à la réouverture (même compte, même poste).
  3. Rendre ma copie (Ctrl+S) → nom, prénom, classe → choisir Copies\<classe> la première fois. Une nouvelle copie remplace la précédente.

Après : l'enseignant corrige

  1. Examen → Ouvrir un dossier de copies… → Copies\<classe> : notes sur 20, copies manquantes, copie rendue avec le sujet d'un autre élève, détail et journal par élève, fiche de recette et tirs OTDR.
  2. Ajuster le barème si besoin ; Exporter (CSV) vers Enseignant\Notes (tableur, Pronote) ; Imprimer les fiches individuelles.
IncidentSolution
La copie est arrivée dans Téléchargementsl'élève la dépose dans Copies\<classe> (glisser-déposer)
« Écriture impossible dans ce dossier »vérifier les droits (section 3) ou utiliser l'archive .zip
Copie signalée « sujet de … »l'élève a ouvert le sujet d'un camarade : à traiter avec lui

5. Maintenance et sécurité

Calendrier

QuandAction
Rentréenouveau mot de passe ; reconstruire les paquets ; relancer creer-partage.ps1 (nouvelles classes) ; mettre à jour le site public
Nouvelle version d'OptiSimtests (node outils/tests.js et node outils/tests-navigateur.js), puis remplacer Application et Enseignant\Version-enseignant (le script le fait avec -PaquetEleve et -PaquetEnseignant) ; publier le site avec outils/publier-site.js
Après chaque épreuvedéplacer les copies de Copies\<classe> vers Enseignant\Archives ; conserver le CSV des notes
Fin d'annéesauvegarder Enseignant (archives, notes, dossiers techniques) ; vider Sujets et Copies

Ce qui protège quoi

ÉlémentProtection
Version enseignant sur le partage ou le sitechiffrée (AES-256, mot de passe) et dossier invisible pour les élèves
Sujets et copiesencodés (illisibles dans un éditeur de texte), mais pas chiffrés : les droits du partage font la protection
Copies des camaradesdépôt seul : un élève ne voit pas les fichiers des autres
Code source (corrigés en clair)dépôt GitHub privé ; seul le site construit est public

Limites : une application hors ligne ne peut pas empêcher un élève déterminé de copier un fichier qu'il peut lire. Pour une épreuve certificative, ajouter la surveillance habituelle : sujets individuels, Internet coupé, clés USB interdites.
